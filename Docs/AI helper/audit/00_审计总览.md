# 00 XEngine 审计总览

> 范围：整个引擎现有代码（RHI、Vulkan、Renderer、CSM、Scene、Asset、Serialization、Shader、Editor、Sandbox、Build/Core/Math）的子系统级别审计
> 状态：未触动任何源码；所有变更建议以"如果执行 X，请在 Y 处修改"形式呈现
> 生成时间：2026-07-18

---

## 1. Overall Health / 总体健康度

**总体健康度**：⭐⭐⭐（3 / 5）—— 架构骨架清晰，但当前 CSM 路径上有数处 silent bug。

- **架构纪律**：非常好。Scene 不依赖 Renderer/RHI，Asset public header 不暴露 fastgltf/sb/slang，公共 RHI 不直接暴露 Vulkan，Editor 是可选 target，Sandbox 不依赖 Editor；这些都已经做到。
- **Shader↔C++ interop 类型设计**：foundation 级别好；每个 interop struct 都用 `alignas(16)` + `static_assert(sizeof)` 固化 layout。这是后续 Stage 11 PBR Test / Stage 13 IBL 的可靠地基。
- **CSM 拆分子系统粒度**：极好。`ShadowResourceCache` (persistent Texture2DArray) / `DirectionalShadowPlanner` (纯 CPU 数学) / `RenderShadowManager` (orchestrator) / `ShadowDepthPass` (record only)，完全符合提示文档期望方向。
- **代码层面**：Vulkan 转换集中在 `VulkanUtils.cpp`；hot path `dynamic_cast` 走 `VulkanCheckedCast.h`；`RHIUtils` 是空架子（缺失）。
- **最重要的健康问题**：本批 CSM 接入存在 4 处 silent bug，外加 CSM 的 reverse-Z 与 texel-snap 在 CPU 端可读性差。这 4 处修复**立刻可见 shadow**，必须 P0。

## 3. Top 10 最值得保留的设计

1. **`+X Forward / +Y Right / +Z Up / Left-Hand` 约定贯穿**：`Math::*`、`Camera/Transform`、`Light` 方向、shader 取 `viewPos.x` 当 view-space depth —— 全部在"同一条语言"上。详见 [01 §3.2](01_Core与Math审计.md)、[05 §6](05_CSM阴影系统审计.md)。
2. **Scene / Asset 不依赖 Renderer/RHI 的边界纪律**：[06 §2](06_Scene_Asset_Serialization审计.md) 中保持干净。
3. **shader interop struct 严格 layout 校验**：`GPUFrameData`、`GPUCascadeShadowData` 的 `static_assert(sizeof)` 与 Slang 镜像 —— [04 §2](04_Renderer架构审计.md)、[08 §2](08_Shader系统审计.md)。
4. **ShadowResourceCache + 单一 persistent Texture2DArray**：与提示文档 §3 推荐完全吻合 —— [05 §2](05_CSM阴影系统审计.md)。
5. **`Passes` 仅 record、不创建资源**：[`ShadowDepthPass.cpp`](../../Engine/Source/Runtime/Renderer/Private/Passes/ShadowDepthPass.cpp) 与 [`ForwardOpaquePass.cpp`](../../Engine/Source/Runtime/Renderer/Private/Passes/ForwardOpaquePass.cpp) 都不创建 GPU resources，符合 RenderGraph pass 设计原则。
6. **`VulkanUtils` 集中 16 种 RHI↔Vulkan 转换**：所有映射走 `XENGINE_VK_CHECK` + `checked_static_cast` —— [03 §2](03_Vulkan后端审计.md)。
7. **`RenderSystem` 通过 3 个 callback 暴露给 Editor**：`SetOverlayCallback` / `SetViewProvider` / `SetOutputProvider` —— [04 §2](04_Renderer架构审计.md)。Editor 不 override pipeline，仅注入。
8. **`XEngineRuntime` 是 INTERFACE library**：[09 §2](09_构建与项目结构审计.md) —— Sandbox / EditorApp 单一 link。
9. **公共头不暴露第三方**：`MeshAsset.h`、`MaterialAsset.h` 等不 include `fastgltf/`、`sb/`、`slang/` —— [06 §2](06_Scene_Asset_Serialization审计.md)。
10. **`BuildPlan` 与 `RenderFrameContext` 单一载体**：CSM 数学计算结果通过 `RenderFrameContext` 进入 frame，`DirectionalShadowPlanDesc` 是单一入口 —— [04 §2](04_Renderer架构审计.md)。

## 4. 最高风险区域

### 4.1 CSM 整条链（深度优先）

风险 = silent bug 数量 × 影响范围。CSM 中：

- **CPU 端**：3 个 silent bug（P0 立刻修）。
  - `shadowLight = nullptr` —— 函数提前 return。
  - `GPUFrameData::Shadows` 永远是 0。
  - `ShadowDepthPass` pipeline 取 ForwardOpaque pipeline。
- **Vulkan 端**：1 个静默差距。
  - `VulkanSampler` 硬编码 `compareEnable = VK_FALSE`、`borderColor = INT_OPAQUE_BLACK`；当前 PCF 是 manual 9-tap，但范围超出 texel 时 border 行为定义含糊。
- **Shader 端**：1 个稍无声的 potential bug。
  - `ShadowSampling.slang` 与 `Lighting.slang` 用 `>=` 作 reverse-Z bias 比较；这是对的，但 CPU 端 RangeZ 翻转顺序在 C++ 反复改 3 次易出错。

### 4.2 Architecture 边界

- `RHIDevice::GetVulkanNativeContext/...` Vulkan 公共泄漏 —— 这是跨 backend 最大的 risks（见 RHI 审计 §3.1）。
- `Scene/Components.h` 含 `MeshRendererComponent::MaterialAsset`，但 `MeshSubmesh::MaterialSlot` 是 placeholder —— 多 submesh 不工作。
- `BindlessResourceManager` 已实现 skeleton 但本期不做 bindless；如果后续被引入到 CSM 路径会立即破坏"一切 bindless 暂缓"。

### 4.3 Lifetime

- `ShadowResourceCache::GetOrCreate` 在 size 改变时立即释放旧资源，frame bind group 仍引用旧 SampledView / Sampler，**当前没有保护机制**。
- `RendererMaxFramesInFlight` 与 RHI 帧数独立硬编码 `3`，多 backend 移植时必挂。

### 4.4 Cross-platform discipline

- `ImGuiVulkanBackend` 私有于 Editor，本身 OK；但若未来 Editor 跨 backend，需要重写。
- Vulkan 代码用的 vkCreateSampler 的 `borderColor` / `compareEnable` 没有 RHI 接口对应字段，扩 D3D12 时要临时加。

### 4.5 上行耦合 vs 下行耦合

- `Renderer` 引用 `RHI` ✓、Shader / Asset / Scene / Input / Platform / JobSystem / Serialization ✓；Editor 通过 EditorSystem `SetOverlayCallback` 注入到 Renderer。无反向依赖 ✓。

## 5. Roadmap 调整建议

将原计划（Stage 9 → 10 → 11 → ...）插入三个修复窗口：

### 5.1 P0 修复窗口（"Day-1 CSM Fix Pack"）

下列 5 件事在 **Stage 9 末尾** 已可一次 PR 闭环：

1. `shadowLight = nullptr` → `shadowLight == nullptr`。
2. `RenderFrameResources::Initialize` 接收 `RHITextureView* shadowSampledView, RHISampler* shadowSampler`；RenderSystem 顺序：ShadowManager PrepareFrame → SetShadowBindings → FrameResources::Update。
3. `BuildGPUFrameData` 增加 `const RenderShadowManager&` 参数并 fill `data.Shadows`。
4. `RenderPassKind::ShadowDepth` 独立 PassKind、`RenderPipelineStateCache` 加分支。
5. `DirectionalShadowPlanner` 抽 `MakeCascadeProjection(radius, bias, reverseZ)` helper；texel-snap 用同一 helper。

完成这件事后，shadow 在 sample-level 上会真正浮现。

### 5.2 P0-1 CSM 质量窗口（在 Day-1 完成后立即做）

- `VulkanSampler` 加 `CompareEnable/CompareOp/BorderColor` —— 切换到硬件 PCF，PCF5x5 同时可用。
- `ShadowResourceCache` 引入 `INotifyResourceRecreated` 接口，`RenderFrameResources` 实现并 rebind Set 0。
- `DirectionalShadowPlanner::BuildPlan` 用 `SceneBounds` 参与 radius。

### 5.3 Stage 10 (DebugDraw) 与 Stage 11 (PBR Test) 调整

- DebugDraw 之前：
  - 把 `MeshRendererComponent::MaterialAsset` 升级到 `MaterialSlots[]`；
  - `LightComponent` 加 `UseEntityTransform`；
  - `Rotator` 显式单位；
  - `EditorContext::HasValidViewportTexture()`。
- Stage 11 之前：
  - 切到 hardware PCF + sampleCmp 着色；
  - normal map 完整接入；
  - 法线变换 `inverse(transpose(mat3(model)))`。
  - C++ `GPUFrameData.Shadows → Shadow` 与 slang 对齐。

### 5.4 RenderGraph V1 之前

- 引入 layout transition tracker（已预留 `RHITexture::GetLayoutPtr`）。
- RenderGraph Resource version 与 ShadowResourceCache version 关联。
- `RHIDevice` 把 `MaxFramesInFlight` 提升为公共字段。

### 5.5 长期清理

- `BindlessResourceManager` 标注 Stage 13 不在本批动；或删除。
- `RHIUtils` 补 `IsDepthFormat / IsStencilFormat / GetFormatSizeInBytes / GetAspectMask`。
- `gltf`: PBR metal-roughness 全套、`GltfTangentToXEngine` unit test。
- AssetHandle 强类型（typed handle）。

```
[Sandbox]  →  [Editor]   →  XEngineEditor (lib)
              │
              ↓ (callback only)
[Apps]      →  XEngineRuntime (INTERFACE)
              │
              ├── XEngineFoundation  (Core / Math / Logging / Diagnostics)
              ├── XEngineCoreRuntime (Engine / Platform / JobSystem / FileSystem / Input / UI)
              ├── XEngineSerialization
              ├── XEngineAsset       (Private: GltfImporter, MaterialImporter, TextureImporter, ImageImporter)
              ├── XEngineScene       (ECS, no RHI / Renderer)
              ├── XEngineShader      (Slang compiler, ShaderCache)
              ├── XEngineRHI         (Public: RHITypes, RHIDevice, Resources; Private: Vulkan/*  [Bridge: VulkanUtils])
              └── XEngineRenderer    (Per-frame: RenderFrameResources + per-cascade GPUFrameData;

                                     RenderShaderLibrary, RenderPipelineStateCache;
                                     Shadow: RenderShadowManager → ShadowResourceCache + DirectionalShadowPlanner;
                                     Passes: ShadowDepthPass, ForwardOpaquePass, etc.)
              ↑ 仅 Editor / Sandbox 触碰
```
