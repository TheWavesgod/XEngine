## P0 — 继续开发前必须修

> P0 = 静默 bug + 文档边界的"规则违反"，修完后 CSM 才能"动起来"。
> 不修就不能宣称 Stage 9 完成。**预计工作量 0.5~1 天 / 修改 5 处**。

### P0-1 `shadowLight = nullptr` → `shadowLight == nullptr`

- **文件**：[`RenderShadowManager.cpp:124`](../../Engine/Source/Runtime/Renderer/Private/Shadows/RenderShadowManager.cpp)
- **修改**：`if (shadowLight = nullptr) { return; }` → `if (shadowLight == nullptr) { return; }`
- **理由**：当前永远进入函数，CSM 实际根本不准备。
- **验收**：任何启用 `DirectionalShadowTechnique::CascadedShadowMaps` + 一个 `Directional + CastShadow` 灯的场景，shadow 必须出现。

### P0-2 `RenderFrameResources::Initialize` 真正接收 shadow binding

- **文件**：[`RenderFrameResources.cpp`](../../Engine/Source/Runtime/Renderer/Private/Resources/RenderFrameResources.cpp)、[`RenderSystem.cpp:252-256`](../../Engine/Source/Runtime/Renderer/Private/RenderSystem.cpp)
- **修改**：
  - 在 `Initialize` 增加形参 `RHITextureView* shadowSampledView, RHISampler* shadowSampler`（默认 nullptr 兼容旧调用）；
  - 在 `RHIBindingResource { 1, ..., shadowSampledView, nullptr, nullptr, 0, 0 }` 与 `{ 2, ..., nullptr, shadowSampler, nullptr, 0, 0 }` 赋值；
  - `RenderSystem::Render` 顺序调成：
    ```cpp
    ShadowManager->PrepareFrame(device, *activeScene, frame, settings, debug);
    FrameResources->SetShadowBindings(
        ShadowManager->GetFrameData().Directional.SampledView,
        ShadowManager->GetFrameData().Directional.Sampler);
    FrameResources->Update(frame, scene, *ShadowManager);
    ```
- **验收**：`g_ShadowMap.Sample` 在 ForwardOpaquePass 中能取到非空数据，`RenderDoc` 抓帧可以看到 shadow texture descriptor set。

### P0-3 `BuildGPUFrameData` 写入 `data.Shadows`

- **文件**：[`RenderFrameResources.cpp:149-160`](../../Engine/Source/Runtime/Renderer/Private/Resources/RenderFrameResources.cpp)
- **修改**：
  - `BuildGPUFrameData` 增加 `const RenderShadowManager& shadowMgr`；
  - `shadowMgr.FillGPUShadowData(data.Shadows);`
- **验收**：shader 端 `GPUFrameData.Shadow.Cascades[i].LightViewProjection` 不再是 0 矩阵；RenderDoc 抓帧检查。

### P0-4 独立 ShadowDepth PassKind

- **文件**：[`GraphicsPipelineStateKey.h`](../../Engine/Source/Runtime/Renderer/Private/Resources/GraphicsPipelineStateKey.h)、[`RenderPipelineStateCache.cpp`](../../Engine/Source/Runtime/Renderer/Private/Resources/RenderPipelineStateCache.cpp)、[`ShadowDepthPass.cpp:46-49`](../../Engine/Source/Runtime/Renderer/Private/Passes/ShadowDepthPass.cpp)
- **修改**：
  - 新增 `RenderPassKind::ShadowDepth` 枚举；
  - `RenderPipelineStateCache::CreateGraphicsPipeline` 加分支：`kind == ShadowDepth` 时使用 `RenderShaderKey("Passes/DepthOnly.slang")`，HasColorAttachment=false，EnableDepthTest=true，EnableDepthWrite=true，EnableDepthBias=true。
  - `ShadowDepthPass.cpp` 把 pipeline key 的 `PassKind` 设为 `ShadowDepth`。
- **验收**：RenderDoc 抓帧，shadow depth pass 用独立 pipeline；不与 ForwardOpaque pipeline 混淆。

### P0-5 Reverse-Z + texel-snap helper

- **文件**：[`DirectionalShadowPlanner.cpp:307-353`](../../Engine/Source/Runtime/Renderer/Private/Shadows/DirectionalShadowPlanner.cpp)
- **修改**：
  - 抽 helper：
    ```cpp
    static Mat4 MakeCascadeProjection(float radius, float biasSlack, bool reverseZ);
    ```
  - 在 `BuildPlan` 内 `lightProjection = MakeCascadeProjection(radius, desc.DepthBias * 4.0f, desc.ReverseZ);`
  - texel-snap 路径用同 helper 计算 proj。
- **验收**：shadow depth range 与 shader `>=` bias 比较配套；RenderDoc 抓 shadow texture depth 范围应在 `[0, 1]`。

## P0-1 — Stage 10 DebugDraw 期间修

> P0-1 是 CSM 质量 / 视觉一致性，不静默但影响 shadow 细节。

### P0-1-A VulkanSampler 接收 CompareEnable / BorderColor

- **文件**：`RHITypes.h`、`RHIUtils.h`、`VulkanSampler.cpp`、`ShadowResourceCache.cpp`
- **修改**：
  - `RHISamplerDesc` 加 `bool CompareEnable = false; RHICompareOp CompareOp = RHICompareOp::LessOrEqual; RHIBorderColor BorderColor = RHIBorderColor::FloatOpaqueWhite;` (新增枚举)
  - `VulkanSampler` 翻译到 `compareEnable/compareOp/borderColor`；
  - `ShadowResourceCache` 在 directional sampler 上设 `CompareEnable=true`、`BorderColor=FloatOpaqueWhite`（=1.0）；

### P0-1-E `MeshRendererComponent` 多 submesh material slots

## 建议手动实现以加深学习的任务

> 这些任务涉及设计权衡与跨子系统影响，适合开发者手动推进。

1. **CSM Depth Bias 设计**：bias 公式、slope-scaled bias、normal offset —— 与 Pekka、Carsten 等教材对齐。
2. **RenderGraph V1**：cull / aliasing / cycle detect —— 影响所有 pass 写顺序，谨慎。
3. **GPUScene 真实启用**：把 mesh / material 移到 GPU；这是 Stage 13+ 才做的核心架构改动。
4. **IBL Skybox**：cubemap / prefilter / BRDF LUT；与 PBR 一起做但独立子任务。
5. **ASYNC compute：CSM 走 compute queue**：需要 queue family 选择与 synchronization 改造。
6. **多 directional shadow**：当前支持 single directional 加 cascade；multi-light cascade 是 Stage 13+ 的核心。
7. **Dynamic resolution / DLSS / FSR2 路径**：Stage 14+ 跨引擎特性。
8. **Asset bake / serialization migration pipeline**：版本号迁移、CRC、schema 兼容 —— 是 long-term 引擎生产力。
9. **Vulkan bindless 真实实现**：descriptor indexing、update template、partial bindless；与 D3D12 / Metal 桥接。
10. **Material Editor**：复杂 material graph 编辑器；与 Editor 体系深度集成；Stage 15+。
