# 09 构建与项目结构审计

## 1. 审计范围

---

## 2. 当前优点

- **CMake 3.25 + C++20 显式**：顶层 `CMakeLists.txt:1-7` 显式 `set(CMAKE_CXX_STANDARD 20)` + `EXTENSIONS OFF`，干净。
- **Library 分割清晰**：`XEngineFoundation / XEngineSerialization / XEngineAsset / XEngineScene / XEngineInput / XEnginePlatform / XEngineShader / XEngineRHI / XEngineRenderer`，各自有 `add_subdirectory(Source/Runtime/...)`。
- **Editor 是可选**：`XENGINE_ENABLE_EDITOR` 选项，独立 `XEngineEditor` library。
- **`XEngineRuntime` 是 INTERFACE library**：聚合所有 Runtime 子库，方便 Sandbox / EditorApp 单一 link 即可。这是好抽象。
- **GLOB_RECURSE 仅用于 Editor**：CMake 文件 Editor 才 `file(GLOB_RECURSE ... CONFIGURE_DEPENDS)`，因为 Editor panel 数量会随设计增长；这是务实选择，但需要 CMake reconfigure 才能新增文件。
- **选项矩阵集中**：`XENGINE_ENABLE_VULKAN` / `XENGINE_ENABLE_SDL` / `XENGINE_SDL_LINK_SHARED` / `XENGINE_ENABLE_SHADER_COMPILER` / `XENGINE_ENABLE_EDITOR` / `XENGINE_ENABLE_TRACY`。

## 3. 发现的问题

### 3.1 [High] `PUBLIC` / `PRIVATE` header 划分不完全

- **相关文件**：[`Engine/CMakeLists.txt`](../../Engine/CMakeLists.txt)
- **问题描述**：
  - RHI 当前所有 subdir 只用 `add_subdirectory(Source/Runtime/RHI)`，但具体每个库（比如 `XEngineRHI`）target include 细节要在 RHI/CMakeLists.txt 看；
  - Renderer 公共 header 暴露 `Material.h` / `Mesh.h` 等；但应当谨慎避免暴露 fastgltf / Vulkan / Slang；提示文档要求"RHI 不暴露 Vulkan types" 与"公共 RHI headers 不能暴露 Vulkan types"。
  - 从 Renderer 公共 header 看：[`Material.h` 用 `XEngine/Core/Handle.h` + `XEngine/Renderer/MaterialTypes.h`](../../Engine/Source/Runtime/Renderer/Public/XEngine/Renderer/Material.h)。这是 OK；但每个 Renderer public header 都应当被审计，确保不引用 `RHI/RHITypes.h` 中的 Vulkan 字段。
- **推荐修复方式**：
  - 在 `XEngineRenderer` 上加 `target_include_directories(PUBLIC Source/Runtime/Renderer/Public)`，并精确 PRIVATE `Source/Runtime/Renderer/Private`；
  - 加 grep "vulkan|fastgltf|sb|slang" 在公共头；
- **建议**：现在修（P0）。

### 3.2 [High] `Engine/CMakeLists.txt` 用 `file(GLOB_RECURSE)` for Editor

- **相关文件**：[`Engine/CMakeLists.txt`](../../Engine/CMakeLists.txt)
- **问题描述**：
  - `GLOB_RECURSE` 配 `CONFIGURE_DEPENDS`，新增 Editor 文件不需改 CMake。但 Static Library 必须每次 CMake 重新跑，conan-style generator 也得跑。
  - 当前 GLOB 引用 `Source/Editor/*.h` 与 `*.cpp` 同时收集；但 `Source/Editor/Private/ImGui/*.h` 也是 Editor 私有的；
  - 这是 OK，但应当在每个 subdir build (`add_subdirectory(Source/Runtime/Editor)`) 而非顶层 GLOB。
- **推荐修复方式**：
  - 把 Editor 收到 `Engine/Source/Editor/CMakeLists.txt`，跟其他模块一致；
  - 用 `target_sources(XEngineEditor PRIVATE ...)` 显式 add。
- **建议**：Stage 14 期间改。

### 3.3 [High] `XEngineRuntime` INTERFACE 拓扑顺序

- **相关文件**：[`Engine/CMakeLists.txt`](../../Engine/CMakeLists.txt)
- **问题描述**：`XEngineRuntime` target_link_libraries 列举子库，但顺序：Foundation → CoreRuntime → Serialization → Asset → Input → Scene → Platform → Shader → RHI → Renderer。所有 PUBLIC。
- **推荐修复方式**：当前是 OK 的；如果未来加 `XEngineJobSystem`、`XEngineUI` 等也只需补一行。
- **建议**：保持。

### 3.4 [High] `XENGINE_SDL_LINK_SHARED` 默认 ON

- **相关文件**：[`CMakeLists.txt:11`](../../CMakeLists.txt)
- **问题描述**：`XENGINE_SDL_LINK_SHARED ON` 默认 SDL 是动态库。Windows 上需要 SDL3.dll 一起分发；debuginfo 和 ABI surface 风险更大。建议让 CMake 默认 STATIC，便于 one-shot executable。
- **推荐修复方式**：默认改 `OFF`。**这是 build configuration 改动，但**建议。
- **建议**：Stage 14。

### 3.5 [High] `XENGINE_ENABLE_TRACY` OFF，但 ProfilerPanel 已经在 Editor

- **相关文件**：[`CMakeLists.txt:14`](../../CMakeLists.txt)
- **问题描述**：默认 Tracy 关闭，但 ProfilerPanel 已经存在并 references Tracy header。当 `XENGINE_ENABLE_TRACY=OFF` 时 panel 应当 present empty UI 或隐藏。当前未审。
- **推荐修复方式**：在 `XEngineDiagnostics` library 与 Tracy 之间加 `if(XENGINE_ENABLE_TRACY)`，让 ProfilerPanel 在 OFF 时显示 "Tracy disabled"。
- **建议**：Stage 14。

### 3.6 [Medium] `add_subdirectory(ThirdParty)` 把 glfw / fastgltf / imgui / json / SDL / glm 直接 cmake-build

- **相关文件**：[`CMakeLists.txt:16`](../../CMakeLists.txt)、[`ThirdParty/*/CMakeLists.txt`](../../ThirdParty/)
- **问题描述**：当前每个 third-party 都通过 `add_subdirectory` 与 XEngine 一起构建。这是 monolithic 风格，**优点是单一 cmake 配置可控；缺点是 third-party 版本升级困难**。
- **推荐修复方式**：保持当前 monolithic；未来若 project 需要多 project build，可引入 `cmake/build_thirdparty.cmake`，但 V0 不必要。
- **建议**：保持。

## 4. 架构边界问题

- **Module layering**：
  - `XEngineFoundation` (Core + Math + Logging + Diagnostics) → `XEngineCoreRuntime` (Engine/Platform/JobSystem/FileSystem/Input/UI) → `XEngineSerialization` → `XEngineAsset` → `XEngineScene` → `XEngineShader` → `XEngineRHI` → `XEngineRenderer`。
  - **方向 ok**，但**ScriptSystem / JobSystem / UI** 是孤立模块，没有 connect 到 Renderer。这是有意的（Stage 14+）。
- **Editor**:Public：仅消费 `XEngineRuntime`。
- **Sandbox**:Public：仅消费 `XEngineRuntime`。
- **没看到** `XEngineRenderer` 在 `XEngineEditor` 上有 PRIVATE 链接（这是对的）。
- **RHI 是 Runtime 一部分**：意味着 D3D12/Metal 接入需要在 RHI module 加 backend code —— 这与提示文档"未来支持 D3D12 / Metal"路径匹配。
